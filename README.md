# chahua

自然材料拼贴海报 → 小红书文案 → 手工制作过程视频的稳定复用 Skill。

核心 Skill：`skills/chahua-pipeline/SKILL.md`

## 默认模式：FAST

现在默认采用“快速成功路径 + 失败时诊断”的执行方式：

1. 当天联网并行搜索 2–3 组候选方向，选 1 张保存到 `D:\picture`；
2. 在 ChatGPT 中制作自然材料拼贴海报，发送“去掉上半部分。”，保存最终成品到 `D:\picture-output`，并保存小红书标题与简介；
3. 在 Gemini 中严格进入视频模式 → 9:16 → 3.8 Flash + Extended Thinking → 确认视频模式仍激活 → 上传拼贴图 → 注入并验证完整提示词 → 生成 → 下载归档。

**Gemini 视频成功下载后整个流程立即结束。默认不抽帧、不播放、不做视频内容 QA、不等待额外版本。** 只有用户明确要求检查视频质量时才进入 QA。

## 推荐触发语

- `运行 chahua skill，只做 1 张`
- `运行 chahua skill，完整跑一遍`
- `运行 chahua skill，从制图阶段继续`
- `运行 chahua skill，从视频阶段继续`
- `运行 chahua skill，并检查视频质量`（仅此模式会做视频 QA）

默认只处理 1 张图。只有用户明确要求批量时才扩大处理范围。

## 目录

```text
D:\picture              原始候选/最终选中照片
D:\picture-output       最终自然材料拼贴成品
D:\picture-output\video 视频成品
```

## 效率规则

- 启动时不同时访问 ChatGPT 和 Gemini；进入对应阶段时再检查。
- 搜索候选尽量并行，不逐图深度打开。
- 状态只在阶段完成或阻断时写入，不记录每个 UI 点击。
- 页面正常时不截图、不全 DOM 扫描。
- 等待生成使用状态轮询，不使用超长固定 sleep。
- Gemini 提示词发送前必须验证输入框确实有完整内容。
- 下载视频后只确认本地 `.mp4` 存在且非空，然后结束。

Skill 会维护本地运行状态，支持断点续跑，并避免重复搜索、重复生成和下载错文件。
