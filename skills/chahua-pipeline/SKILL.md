# Chahua Pipeline｜自然材料拼贴海报与视频流水线

## 0. 任务目标

把一次创作固定成三个阶段，并允许从任意阶段恢复：

1. **SELECT**：当天联网搜索 2–3 组候选方向，选出最佳 1 张并保存到 `D:\picture`。
2. **POSTER**：在 Chrome 的 ChatGPT 中生成上下对照海报，再去掉上半部分，保存最终拼贴成品，并生成小红书标题与简介。
3. **VIDEO**：在 Chrome 的 Gemini 中使用最终拼贴图生成 9:16 手工制作纪录视频并下载归档。

默认 `max_items=1`。除非用户明确要求批量，否则不得自动扩大到其他图片或文件夹。

---

## 1. 固定目录与状态

### 目录

```text
D:\picture
D:\picture-output
D:\picture-output\video
```

### 状态文件

维护：

```text
D:\picture-output\.chahua-state.json
```

状态至少记录：

- `run_id`
- `date`
- `stage`: `select | poster | video | done | blocked`
- `source_image`
- `source_url`
- `selection_score`
- `poster_chat_created`
- `poster_first_generation_done`
- `poster_final_image`
- `xiaohongshu_text_file`
- `video_input_image`
- `video_downloaded_file`
- `last_error`

每完成一个不可逆步骤立即更新状态。恢复运行时先读状态，再检查实际文件，不要仅依赖状态文字。

### 命名建议

原图：

```text
YYYYMMDD_<scene-keyword>_source.<ext>
```

最终拼贴：

```text
YYYYMMDD_<scene-keyword>_collage.<ext>
```

小红书文案：

```text
YYYYMMDD_<scene-keyword>_xiaohongshu.txt
```

视频：

```text
YYYYMMDD_<scene-keyword>_making.mp4
```

不得覆盖原图。遇同名文件时追加 `_02`、`_03`。

---

## 2. 执行前能力门

开始前按顺序检查：

1. 授权的桌面控制能力可用，能够读取 Windows 文件系统并执行基本文件操作。
2. `D:\picture`、`D:\picture-output`、`D:\picture-output\video` 存在；不存在则创建。
3. Chrome 可启动。
4. ChatGPT 页面可访问并已具备当前会话所需的图片生成功能。
5. Gemini 页面可访问并具备视频创建功能。

注意：**选图阶段只依赖公开网络搜索，不依赖任何网站登录态。** ChatGPT / Gemini 属于后续制图与视频阶段，需要页面本身可用。

如果某一能力门失败：写入 `stage=blocked` 与 `last_error`，停止在该阶段。不要假装已经执行，也不要用其他模型、其他比例或其他网站静默替代。

# 第一阶段：SELECT｜选图

## 3. 每日搜索策略

每次运行重新搜索当天候选，不直接复用旧图，除非用户明确要求从现有图片继续。

一次搜索 **2–3 组不同候选方向**。优先从下列方向中随机或轮换组合，避免每天高度同质化：

- 城市天际线 / 黄昏城市 / 夜幕初起
- 湖景 / 海边 / 河岸 / 倒影
- 山川 / 云海 / 雾景 / 雪山
- 田野 / 梯田 / 农作 / 乡野慢生活
- 雪景街道 / 雨后街道 / 秋日街道
- 古镇 / 巷弄 / 老街 / 骑楼 / 石板路
- 森林 / 林间小路 / 晨雾
- 有行走人物、劳作身影、自行车、车辆等点缀的生活场景

禁止把动物特写、单一植物特写、纯人物肖像作为候选主图。

优先选择无需登录即可访问原图、分辨率足够、来源清晰的公开图源。若同等质量，优先可明确下载与复用的来源。保存来源页面 URL 以便追溯。

## 4. 选片硬门

候选图必须同时满足：

1. 风景或街景类构图为主体；人物 / 生活元素只能增强故事，不可变成纯肖像。
2. 主体形态清晰、前中后层次或空间层次明确，适合用叶片、花瓣、枝条、种子、树皮等自然材料分层重构。
3. 有意境或叙事氛围，例如黄昏、晨雾、雪、田野、慢生活、人物行动等。
4. 色彩氛围鲜明、有辨识度，能提取 2–4 个主配色关系。
5. 有明确视觉重心，同时保留可呼吸的留白。
6. 横竖构图均可，不因原图比例淘汰。

### 排除项

出现任一项直接淘汰：

- 主体过碎，无法辨认主轮廓；
- 画面全是密集纹理，没有层次；
- 纯大头人像；
- 单一花朵 / 树叶 / 动物特写；
- 水印严重遮挡；
- 分辨率明显不足；
- 原图下载必须登录且没有公开可替代源。

## 5. 评分法

对通过硬门的候选按 6 项分别打 0–5 分：

- 场景适配度
- 手工拼贴可重构性
- 意境 / 叙事感
- 色彩辨识度
- 重心与留白
- 清晰度与可下载性

满分 30。优先选择总分最高者；建议入选线 `>=24`，且任何核心项不得低于 3。

若最高分低于 24，不凑数，重新搜索 1 轮。

## 6. 下载与登记

选中后：

1. 打开来源页确认不是缩略图。
2. 下载可获得的高质量原图。
3. 保存至 `D:\picture`，不得覆盖现有原图。
4. 在状态文件中记录来源 URL、搜索方向、评分与最终文件路径。
5. 确认文件可正常打开后才进入 POSTER。

# 第二阶段：POSTER｜制图与小红书文案

## 7. 浏览器自动化原则

优先使用可见文字、ARIA / 语义控件定位按钮，不使用固定屏幕坐标。页面变化时根据“新聊天 / 创建图片 / 添加照片和文件 / 下载”等可见语义重新定位。

**不要使用长时间固定 sleep。** 采用“动作 → 检查页面状态 → 短间隔轮询”的方式。只要生成仍显示进行中，就不要重复发送同一条提示词。

浏览器动作失败可重试 1 次；模型正在生成不属于失败。

## 8. ChatGPT 制图步骤

1. 启动或切换到 Chrome。
2. 打开 `https://chatgpt.com/`。
3. 新建聊天。
4. 进入“创建图片”能力。
5. 点击“添加照片和文件”。
6. 上传本次 `source_image`，只上传当前 1 张。
7. 读取 `prompts/poster.md` 中的 **主海报提示词**并完整发送。
8. 等待生成完成；确认页面已经出现完整生成结果。
9. 在同一聊天中发送精确指令：`去掉上半部分。`
10. 等待第二次生成完成。
11. 只下载第二次生成的“去掉上半部分”成品，不要误存第一次上下对照图。
12. 将下载结果移动 / 重命名到 `D:\picture-output\YYYYMMDD_<scene-keyword>_collage.<ext>`。
13. 确认最终文件存在且可打开，再继续。
14. 在同一聊天发送：`给我一个小红书笔记版本的五个字以内的标题和图片简介，简介要排版精美符合小红书特色。`
15. 将返回的标题与简介原样保存为对应 `_xiaohongshu.txt`，并在最终汇报中同时输出。

### “去掉上半部分”的故障兜底

第一次必须先发送用户指定的短指令 `去掉上半部分。`。

只有当模型明显误解（例如仍保留上下两块、重新设计、改变下半部分）时，才允许补充一次：

> 仅保留上一张图的下半部分自然材料拼贴成品；删除整个上半部分照片区域。保持下半部分的主体、构图、文字、材料、色彩和细节不变，输出为单张 3:4 竖版成品图，不要重新设计。

不要无条件多生成一次。

## 9. 最终拼贴图 QA

进入 VIDEO 前确认：

- 只有自然材料拼贴成品，不再包含上半部分原照片；
- 主体仍可辨认；
- 能看清真实叶片、花瓣、枝条等材料感；
- 没有完整黑色主体描边；
- 没有儿童树叶贴画感；
- 构图留白、重心、越界关系仍合理；
- 下载的是本轮当前图，不是旧下载文件。

若仅是审美轻微偏差，不自动消耗一次新生成；记录 QA 结果并继续。若结构错误（仍有上半部分、文件损坏、下载错图），必须修复后再继续。

# 第三阶段：VIDEO｜Gemini 手工制作纪录视频

## 10. Gemini 配置硬约束

1. 在 Chrome 新建标签页。
2. 打开 `https://gemini.google.com/app`。
3. 新建聊天。
4. 进入 `Create video`。
5. 模型选择用户指定的 **3.8 Flash**（页面实际可见标签可能存在大小写或空格差异，但必须语义匹配 3.8 + Flash）。
6. 开启 `Extended Thinking`。
7. 画幅必须选择 **9:16**。这是竖屏硬约束；不得误选 16:9。
8. 上传 `poster_final_image`，且只上传当前最终拼贴图。
9. 读取 `prompts/video.md` 并完整发送。
10. 等待视频生成完成。
11. 点击下载。
12. 找到本轮最新下载的 `.mp4`，核对创建时间，移动 / 重命名到 `D:\picture-output\video\YYYYMMDD_<scene-keyword>_making.mp4`。

### 模型或选项缺失

如果页面找不到“3.8 Flash”、Extended Thinking 或 9:16：

- 重新检查一次当前视频创建面板；
- 仍不存在则 `stage=blocked`；
- 不得自行替换成别的模型、关闭 thinking 或改为 16:9。

## 11. 视频 QA

下载后至少检查：

- 文件存在且大小非 0；
- 画幅为竖屏 9:16；
- 有真实工作台、真实自然材料与人手操作；
- 材料由手移动，没有漂浮、粒子聚合、自动生长或魔法生成；
- 后段能看到作品接近参考图；
- 最后约 1 秒为成品静态展示；
- 最终构图没有明显被重新设计或增加新主体。

生成模型无法被假定为像素级必然一致，因此 Skill 的职责是：把参考图声明为唯一视觉真值并做结果核验。若内容 QA 未通过，默认**不自动再次消耗生成额度**，而是报告具体失败项；只有用户明确开启 `auto_retry_quality=true` 时，才允许针对失败点重试 1 次。

技术性失败（页面报错、上传失败、下载失败）允许自动重试 1 次。

---

# 12. 防重复规则

每次运行前同时检查：

1. `.chahua-state.json`；
2. `D:\picture` 是否已有当天同源原图；
3. `D:\picture-output` 是否已有对应 `_collage`；
4. `D:\picture-output\video` 是否已有对应 `_making.mp4`；
5. 当前 ChatGPT / Gemini 页面是否已有仍在运行中的同一任务。

若某阶段产物已存在且通过 QA，从下一阶段继续，不重复生成。

禁止因为“没看到按钮变化”而连续重复点击生成。

---

# 13. 运行模式

### 默认：single

一次只处理 1 张，从 SELECT 跑到 VIDEO。

### resume

用户说“从制图继续 / 从视频继续 / 接着上次”时，先恢复状态并检查文件，再从最早未完成阶段继续。

### batch

只有用户明确说“批量”才启用。批量也必须逐张串行执行，每张独立 ChatGPT 对话和 Gemini 视频任务，不能把多张图混进同一个制作对话。

---

# 14. 最终输出

全程使用简体中文汇报。完成后给出：

- 当天搜索的 2–3 个候选方向；
- 最终选图与 30 分评分；
- 原图本地路径；
- 最终拼贴图路径；
- 小红书标题与简介；
- 视频路径；
- 如有失败 / 降级，明确指出发生在哪一步。

成功条件是实际文件落盘，不是页面显示“已生成”。

---

# 15. 禁止事项

- 不得一次默认处理多张；
- 不得覆盖原始照片；
- 不得用动物特写、单一植物特写、纯人像替代目标题材；
- 不得只下载搜索缩略图；
- 不得把第一次上下对照海报误当最终成品；
- 不得用固定坐标硬点 UI；
- 不得用超长固定等待代替状态检查；
- 不得在 Gemini 缺少指定配置时静默换模型；
- 不得把 9:16 改成 16:9；
- 不得声称“100%一致”已经实现而不做 QA；
- 不得重复生成已经完成且可用的阶段。
